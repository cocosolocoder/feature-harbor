# FeatureHarbor

产品意见与公开路线图。

需要Node.js 24 或更新版本。直接运行 TypeScript，不需要安装其他包。

查看命令帮助：

```sh
node server.ts --help
```

启动本地服务：

```sh
node server.ts serve --host 127.0.0.1 --port 8080 --data-dir data
```

打开 http://127.0.0.1:8080 查看首页。Ctrl+C 停止服务。`--data-dir` 指定本地业务数据目录，重启时继续使用同一目录。

接口：

- `GET /health` 返回服务状态和产品名称。
- `GET /api/ideas` 返回意见列表（`{ideas: [...]}`），最新的意见排在最前。
- `POST /api/ideas` 提交新意见，请求体为 JSON 对象：`title`（必填，去掉首尾空白后非空、最多 120 字）、`description`（必填，须含非空白内容、最多 5000 字）、`scenario`（可选字符串，省略视为空、最多 1000 字），长度按 Unicode 码点计算。成功返回 201 和 `{idea: {...}}`，包含 `id` 与 `createdAt`；字段缺失、类型或内容不合要求返回 400。
- 未知路径返回 404，已知路径不支持的方法返回 405。
- 首页 `/` 提供提交表单和意见列表，数据保存在 `--data-dir` 指定的目录中，重启后保留。

```sh
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/api/ideas
curl -X POST http://127.0.0.1:8080/api/ideas \
  -H 'content-type: application/json' \
  -d '{"title":"支持深色模式","description":"希望界面支持深色模式。","scenario":"夜间使用"}'
```

## 自动化回归测试

回归测试补充在 `test/` 目录，覆盖首页“首次列表加载”与“提交意见”之间的展示行为，以及接口字段规则：

- 提交成功：保存成功提示、清空标题/详细说明/使用场景、新意见展示在已有记录之前，字段与提交时间对应原记录。
- 首次列表与提交先后返回两种竞态：已保存意见始终可见、不被晚到的列表覆盖。
- 按意见 `id` 去重：同一条只显示一次；标题正文相同但 `id` 不同的两条分别展示，不按文字合并。
- 同一页面先后提交两条：后提交的在前，原记录保持接口返回次序。
- 加载中不提示“还没有意见记录”；确认为空才提示；加载失败显示失败提示且不清掉已提交意见，失败提示与之后的成功提交同时保留。
- 提交失败（含网络错误）：保留表单内容、给出失败信息、不显示成功、不插入列表、已有记录保留。
- 接口回归：`GET/POST /api/ideas` 的字段规则与长度限制、`/health`、404/405、数据持久化。

浏览器用例通过 `puppeteer-core` 驱动系统已有的 Chrome（不会下载浏览器）。运行测试前安装一次开发依赖，并可用 `CHROME_BIN` 指定 Chrome 可执行文件：

```sh
npm install
npm test
# 或指定浏览器：
CHROME_BIN=/usr/bin/google-chrome npm test
```

接口用例只依赖 Node 内置能力；服务本身仍可像上面一样无需安装任何包直接运行。
